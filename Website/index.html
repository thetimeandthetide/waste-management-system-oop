What This Project Does

Add Records

User enters waste details and clicks Add. Java sends an INSERT query to MySQL.

View Records

The app reads all database rows and shows them in a JTable.

Update Records

Selecting a row fills the form. Edited values are saved with an UPDATE query.

Review Records

Members can flag an entry invalid or request completion. Admin approves the request or marks a selected record collected directly.

Search Records

The search box narrows the records available to the signed-in role.

Generate Reports

Completed collections are summarized by member, category, actual area, and date range.

Join Clean CET

New members submit their name, date of birth, CET register number, and department. The app creates an account and assigns an available area.

Login, Roles, And Reporting

The current desktop build starts at a login screen with Sign in and Join Clean CET actions. New members enter their name, date of birth, CET register number, and department. Their lowercase first name becomes the username; after the account is created, the app randomly assigns an available location and displays the requested username_clean password before opening their member workspace. Duplicate usernames and register numbers are rejected.

The admin can open a Member directory to search profiles and see DOB, CET register number, department, assigned area, and account status. Passwords are never shown there or stored as plaintext. The requested password pattern is predictable and is only appropriate for this classroom project.

A member can add and update their own pending records, flag them invalid, request completion approval, and view only their personal contribution. The admin can review all entries, approve or reject requests, mark selected records collected directly, delete them, and view overall, individual-member, and area reports.

Approval gate

A member request remains pending until admin approval. Only completed records count in reports; rejected requests remain editable and can be resubmitted.

Assigned and bonus

Actual collection at a different location from a member's assigned territory appears as bonus in their personal report. Area totals follow the actual location.

Area accumulation

SQL sums approved kilograms and counts records by actual location and applied date range. It is not a population estimate or scientific pollution index.

Team data note: default MySQL is localhost on each computer, so teammates' separate installs do not sync. Shared records require all installs to be configured for one secured, reachable MySQL host. The weight charts report recorded kilograms, not a scientifically measured pollution score.

OOP Concepts In This Project

Classes And Objects

Each .java file defines a class. Objects are created when waste records are added or read from MySQL.

Encapsulation

Waste fields are private. They are accessed using getters and setters.

Abstraction

Waste is abstract because a general waste object must be categorized by child classes.

Inheritance

OrganicWaste, RecyclableWaste, and HazardousWaste extend Waste.

Polymorphism

getWasteCategory() behaves differently depending on the object type.

Exception Handling

try-catch handles invalid quantity and database errors.

Packages

model, dao, gui, and main separate responsibilities.

Swing Event Handling

Button listeners run actions when the user clicks buttons.

model/Waste.java

Purpose: Abstract parent class for all waste types. It stores common fields and forces child classes to provide a waste category.

public abstract class Waste

Meaning: abstract means we do not create a direct Waste object. We create OrganicWaste, RecyclableWaste, or HazardousWaste.

private int id;
private String description;
private double quantity;
private String location;
private String status;

Meaning: private fields demonstrate encapsulation. Other classes cannot access them directly.

public abstract String getWasteCategory();

Meaning: this abstract method must be implemented by every child class.

public String getDescription()
public void setDescription(String description)

Meaning: getters and setters control access to private data.

model/OrganicWaste.java

Purpose: Represents organic waste records.

public class OrganicWaste extends Waste

Meaning: OrganicWaste inherits common fields and methods from Waste.

@Override
public String getWasteCategory() {
    return "Organic";
}

Meaning: This overrides the abstract method and returns the category Organic.

model/RecyclableWaste.java

Purpose: Represents recyclable waste records.

public class RecyclableWaste extends Waste

Meaning: It reuses the common Waste fields and only changes the category behavior.

return "Recyclable";

Meaning: This is polymorphism because the same method name returns a different value.

model/HazardousWaste.java

Purpose: Represents hazardous waste records.

public class HazardousWaste extends Waste

Meaning: It is a child class of Waste.

Meaning: It gives its own version of getWasteCategory().

Common Viva Questions And Answers

Why did you use Swing?

Swing is built into Java and is suitable for simple desktop applications. It does not need web technologies.

Why did you use MySQL?

MySQL stores records permanently, so data remains even after closing the app.

What is JDBC?

JDBC is Java Database Connectivity. It allows Java programs to connect to databases and run SQL queries.

Why use PreparedStatement?

It makes SQL queries safer and cleaner by separating SQL structure from user values.

What is abstraction in your project?

Waste is abstract and contains the abstract method getWasteCategory().

What is inheritance in your project?

OrganicWaste, RecyclableWaste, and HazardousWaste extend Waste.

What is polymorphism in your project?

The same method getWasteCategory() returns different values depending on the object type.

What is encapsulation in your project?

Fields in Waste are private and accessed through getters and setters.

How does the Add button work?

The Add button event calls addWaste(), creates a Waste child object, then WasteManager inserts it into MySQL.

How does data appear in the table?

WasteManager runs SELECT, converts rows into Waste objects, and the GUI displays them in JTable.
