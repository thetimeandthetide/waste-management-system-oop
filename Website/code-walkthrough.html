Current Build: Every Important File

Java starts at Main, initializes MySQL in a background SwingWorker, opens the login screen, and after authentication opens a role-aware dashboard. Button listeners call GUI handlers; handlers validate input and call manager classes, which execute prepared SQL through JDBC.

main/Main.java

The Java entry point. It shows a startup status window and initializes the database in SwingWorker.doInBackground() so the Swing Event Dispatch Thread stays responsive. It opens LoginFrame after startup succeeds and reports connection errors in a dialog.

gui/LoginFrame.java

Creates the Swing username/password form and the Join Clean CET dialog. Registration collects name, DOB, CET register number, and department; UserManager derives a lowercase first-name username, assigns an unused area, hashes the requested username_clean password, and opens the member workspace after showing credentials once.

dao/AuthenticationManager.java

Finds an active username in app_users, retrieves its stored salt/hash, asks PasswordHasher to verify the entered password, and returns an identity object only when valid.

dao/PasswordHasher.java

Uses PBKDF2WithHmacSHA256 with a per-account salt and repeated key derivation. It compares hash bytes using constant-time comparison and does not store plaintext passwords.

dao/UserManager.java

Validates registration, checks duplicates, locks unassigned-area rows, randomly selects a location, and commits account creation with its area assignment in one transaction. Admin-only methods search profiles and add future registration areas.

model/AppUser.java

Holds the authenticated username, display name, role, assigned area, date of birth, CET register number, and department. Passing this object gives the GUI and DAO the identity/context needed to scope data and permissions.

model/RegistrationResult.java

Short-lived result containing the new member identity and one-time password display value. MySQL stores only the salted hash.

gui/WasteManagementGUI.java

Builds the Swing interface: navigation, record form/table, member completion request, admin approval queue, applied date filters, totals, member and area breakdowns, chart, CSV export, announcements inbox, and logout. ActionListeners connect controls to handlers. Report dates are committed only after successful queries, and export reads that applied range. Record permissions and report privacy are enforced by manager methods, not only by hiding buttons.

gui/CleanButtonUI.java

A small shared Swing button renderer. It explicitly paints each button's background and handles pressed, hover, and disabled states so native operating-system look-and-feels cannot turn a white label on a pale button. The login and dashboard reuse it.

registration_areas

Tracks locations available for new members and the username assigned to each. The administrator can add areas without editing Java source.

model/Waste.java

Abstract parent for waste types. Private shared fields include ID, category-related details, description, quantity, actual location, status, author, credited collector, collection time, and invalid reason. Getters/setters demonstrate encapsulation; getWasteCategory() is abstract.

model/OrganicWaste.java, RecyclableWaste.java, HazardousWaste.java

Child classes inherit shared record fields and override getWasteCategory(). A method call through a Waste reference returns the category for its concrete object, demonstrating polymorphism.

model/ReportSummary.java

Small data object for top-level totals, category quantities, and counts returned by report queries.

model/ReportRow.java

Data object for a row in member-wise or area-wise tables, including category splits and assigned/bonus totals where relevant.

model/Announcement.java

Immutable data object carrying the announcement title/message, author, timestamp, and this account's read state.

dao/DatabaseManager.java

Reads database settings from system properties/environment, opens Connector/J connections with DriverManager, creates the database/tables, adds missing columns without dropping old data, normalizes older statuses, seeds the admin plus original 13 members if absent, and seeds registration areas.

dao/WasteManager.java

Owns record SQL and role/ownership checks. Members can request completion for their own pending records; the admin approval/rejection queue uses database transactions so approval and marking collected happen together. Editing, invalidating, or directly completing a record cancels stale requests.

dao/ReportManager.java

Uses parameterized date filters and SQL aggregates (SUM, COUNT, grouping/joins) to calculate completed totals, category splits, member reports, area reports, and personal assigned-vs-bonus figures.

dao/AnnouncementManager.java

Allows only an administrator to publish, lists notices for the signed-in account, counts unread messages, and records when a member opens a notice.

completion_requests

Stores each member completion request, its request time, pending/approved/rejected/cancelled status, and the administrator and time of review. The admin dashboard refreshes its pending count every 15 seconds when all clients use the same MySQL server.

sql/setup.sql

Non-destructive schema reference for manual setup. It does not drop a database. Normal startup uses DatabaseManager to create/migrate tables and seed the initial accounts.

build.sh / build.bat

Compile the Java packages with the bundled Connector/J JAR and package a runnable JAR with the manifest.

run.sh / run.bat

Start the packaged JAR. MySQL must be running and environment variables must be set first if using non-default credentials.

Current database fields and meanings

app_users: username, display_name, assigned_area, role, password_salt,
           date_of_birth, register_number, department,
           password_hash, active
registration_areas: area_name, assigned_username
announcements: id, title, message, created_by, created_at
announcement_reads: announcement_id, username, read_at
completion_requests: id, waste_id, requested_by, requested_at,
                     request_status, reviewed_by, reviewed_at
waste: id, waste_type, description, quantity, location, status,
       created_by, collected_by, collected_at, invalid_reason,
       created_at, updated_at

created_by says who entered the record; collected_by says whose personal contribution is credited. Quantity is kilograms. The actual location is used in area reports. If it differs from the collector's assigned area, it is classified as that member's bonus contribution.

Report rules and permissions

Members can register, add/update/invalidate their own pending records, request completion approval, see only their own contribution, and read admin announcements. Admin sees all records/reports, can search member profiles, add registration areas, mark pending records collected, approve/reject member requests, delete records, and publish notices. Only completed records count in reports. One normalized waste table is the source of truth; SQL computes reports when requested, so there are no separate report tables to synchronize.

Area reports sum approved waste weight and count records by the actual collection location. This describes recorded waste accumulation, not the number of people in an area or a scientific pollution index. Applying a date range updates the report; CSV export uses the last successfully applied range.

JDBC connection and MySQL setup

Connector/J is the JDBC driver implementation. DriverManager.getConnection() opens a Connection; PreparedStatement binds values; ResultSet reads SELECT output. Configuration variables are WASTE_DB_SERVER, WASTE_DB_NAME, WASTE_DB_USER, and WASTE_DB_PASSWORD. The default host is localhost, so each teammate's laptop has separate data until all are configured for a common secure MySQL server.

USE waste_management_db;
SHOW TABLES;
DESCRIBE app_users;
DESCRIBE waste;
SELECT username, display_name, role, assigned_area FROM app_users;
SELECT id, waste_type, quantity, location, status, collected_at, collected_by
FROM waste ORDER BY collected_at DESC;

Important limitations to explain honestly

Reports show entered waste weight by category and location, not a measured pollution score. Announcements are one-way broadcasts with read receipts, not real-time push or two-way chat. This Swing client applies role checks, but direct database access can bypass client-side authorization; production use needs centralized authorization and protected credentials. The website is a separate learning guide; Firebase does not host the Java desktop app or MySQL database.

How To Run The Project

1. Start MySQL

brew services start mysql

This starts the MySQL server in the background. The Java app needs MySQL running before it can store or read data.

2. Open The DesktopApplication Folder

cd /path/to/WasteManagementSystem/DesktopApplication

Replace the path with the folder where you downloaded or cloned the repository.

3. Run The App

./run.sh

This runs the packaged JAR file. The Swing desktop window opens. On Windows, run run.bat from this same folder.

4. Rebuild If Code Changes

./build.sh

This compiles the Java source files and recreates dist/WasteManagementSystem.jar. On Windows, run build.bat.
